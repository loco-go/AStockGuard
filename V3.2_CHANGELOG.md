# V3.2 — Level2 Platform

## Added

- Unified `Level2Snapshot`, bid/ask level and trade models.
- `Level2Provider` abstraction so authorized providers can be added without changing UI/business logic.
- `MockLevel2Provider` with deterministic ten-level bids/asks and recent trades for UI and replay development.
- `HttpJsonLevel2Provider` for authorized HTTPS services using `GET /level2?symbol=...` and optional bearer token.
- Room `level2_snapshot` cache with database migration 6 → 7.
- Cache fallback is marked `STALE`; an unavailable real provider is never silently replaced with mock data.
- Compose Level2 card with sell-10 → sell-1, buy-1 → buy-10 and recent trades.
- Level2 source status is explicitly labeled as MOCK, authorized real source, or STALE cache.
- Settings for provider type, HTTPS base URL and encrypted Level2 token.
- Level2 connection test in Settings.
- AI prompt only uses Level2 as live evidence when `simulated=false`; MOCK data is explicitly excluded from real-trading evidence.
- Backup/restore includes provider type and base URL but never exports the Level2 token.

## Provider contract

`HTTP_JSON` expects an authorized HTTPS endpoint:

`GET {baseUrl}/level2?symbol=000001.SZ`

Example payload fields:

- `symbol`
- `ts`
- `source`
- `bids`: `[ { "price": 10.00, "volume": 12000 } ]`
- `asks`: `[ { "price": 10.01, "volume": 8000 } ]`
- `trades`: `[ { "time": "10:21:31", "price": 10.01, "volume": 500, "side": "BUY" } ]`

## Boundary

This version does not claim to decode any proprietary broker or third-party Level2 protocol. A real provider/decoder should only be added when its authorized protocol or captured field definition is available.
